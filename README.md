# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 励磁域规则

励磁的业务规则集中在 `frontend/src/data/excitation.ts`（纯函数，只改草稿状态），
编排与落库在 `frontend/src/api/local-service.ts`。

- **退出即冻结**：装置「退出运行」时记录退出日期，强励次数定格，之后「登记强励」直接拒绝；
  同一台装置重复点退出只算一次（第二次起拒绝且无任何副作用），不会多扣台数。
- **异常口径**：待检查才算待办、异常才算异常台数，已退出两者都不算；概览页的待处理 /
  异常量与装置列表的台数因此始终一致，装置退出后概览待检查数跟着回落。
- **强励冲回规则**：以退出日期为界，检查日期晚于退出日期的励磁记录整笔记回、不计入
  强励次数；冲回额写入装置「强励冲回」留痕（如 5→3）。回填每次从记录整体重算，而不是
  在上次结果上再减，因此重复回填、重复退出都不会多冲一次。
- **两条回填路径的先后与冲突处理**：先按**登记时间**整体落库归档（缺装置编号或检查日期
  的早期记录不参与计数，另列一行回填说明），再按**检查日期**重放计数。补登记录
  （登记晚、检查早）归档顺序不动、计数按检查日期重算；同一检查日期多条按登记时间先后。
  回填与换版重算同时触发时，先回填出次数、再按现行标准出结论，同一次原子落库。
- **换版重算**：判定标准在 `frontend/src/data/standards.ts`（当前 2026版）。换版只需改
  版本号与阈值，下次进入系统自动按新版重算全部已有记录；旧结论保留当时等级并注明版本
  （如「正常（2025版）」），页面上也可手动「按 2026版 标准重算」。
- **同源显示**：装置列表、另存清单（CSV 导出）、概览统计取的是同一份状态，页面显示什么，
  导出就是什么，不会残留旧值。
- **提醒与待办同源**：退出装置的结论写回机组检修的待办清单，励磁页的提醒事项与检修页的
  待办清单取的是同一份数据，任意一侧标记完成，另一侧同步。
- **原子落库**：每次操作先在草稿状态上整体改完，再一次写入 localStorage；写成功才换内存
  缓存，写失败（如配额满）整体回滚，不会只写进去半条记录。
