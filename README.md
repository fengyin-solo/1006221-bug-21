# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 口径与规则版本（v2.0）

规则版本常量在 `frontend/src/data/types.ts`，换版引擎在 `frontend/src/data/migration.ts`。
首次打开读到旧版（v1.0）数据时自动整库迁移一次，迁移幂等：已有 v2.0 版本戳的记录不再重算，
终态旧结论保留当时等级并注明「v1.0 旧档」，不覆盖。

### 励磁装置（excitation）

- 装置「退出运行」后**强励次数立即冻结**，页面上的「记录强励」对已退出装置直接拒绝，计数不再累加。
- 异常装置台数只统计状态为「异常」的在役装置，**已退出装置不计异常**；待检查口径同样排除已退出，
  所以概览上的待检查装置数会随退出回落。
- 同一台装置重复点「退出运行」只算一次（已是终态会被拒绝），不会多扣台数。
- 页面列表、统计卡、概览、另存 CSV 取的是同一份 `listRows` 数据，强励次数与异常台数必须一致；
  CSV 末尾附统计口径行与逐行回填说明。

### 历史回填（两条路径）

1. **路径一（整体回填）**：历史数据按「登记时间」整体回填，登记时间取自各模块的登记/检查日期字段
   （`modules.ts` 的 `dateField`），全库按登记时间升序排列。早期缺该字段的模块（如机组检修）或
   缺有效强励次数的记录不臆造，另列一行「回填说明」，同时进入提醒清单催人工补录。
2. **路径二（励磁专项）**：励磁历史记录按「检查日期」重放强励流水，退出装置退出日之后多记的强励
   次数一律冲回，计数冻结为退出日（含）前最后一笔流水值；无流水可查时保持现值并注明待人工核对；
   退出时间缺登记时按检查日期回填。

**先后与冲突处理**：先跑路径一、再跑路径二；两条路径对同一字段有分歧时专项规则（路径二）优先。
登记时间与检查日期语义不同，两者都保留——业务判定以检查日期为准，登记时间只用于排序与审计。

### 机组检修（overhaul）

- 办理完工后结论「已完成（v2.0）」写回工作票本身，页面列、另存 CSV、运营概览的待办清单三处取的
  是同一份结论，不会再出现页面已完成、导出残留旧值。

### 待办、提醒与落库

- 待办清单与提醒事项都由 `local-service.ts` 从同一份库派生（`listTodos` / `listReminders`），
  动作落库后两边同时刷新；提醒来源分到期待办与回填说明两类。
- 所有写入走 `local-store.commitAll()`：先在内存生成整套下一版数据，序列化成功后一次性写
  `localStorage`；序列化或写盘任一步失败都恢复旧库，整套回滚，不允许只写进去半条记录。
